## 选择要点

- 同一版式不宜连用太多页，但**可读性优先于花样**。
- 长名字用整行（rows/proj/college），不塞窄栏（flow/grid2/bh）。
- **rows／proj／college 画出来都是“整行白卡往下叠”，视觉上算同一种**：一套课件里别让它们占满（示例 v1 因此被批千篇一律）。数字用 sum、先后用 flow/steps、一分为二用 fork、四项并列用 grid2、密集清单用 bh、想画出关系用 htree、名单用 chips、三档总览用 podium。
- 主题包只换皮；用户说“换个风格”多半指**版面骨架**，要出版面方向对比（见 style-picking.md「版面方向」）。
- 不同项目独立成块，不把两个项目挤进一张卡。
- 标签与正文重复的备注不显示；同列重复标签只显示一次。
- 数字放大只用于 sum；其他页不自动加粗、不高亮。

## 骨架里未启用的旧版式（不要重名、不要启用）

branch / compare / path / metrics / timeline / ladder / bit-*… 仍在骨架 CSS 里。新版式名与它们重名会被带出旧效果（曾因 `timeline` 重名多出竖线；`bit-cooperation` 把标题字号写死成 `!important`，单字段字号失效）。新增版式时先 `grep` 骨架确认不重名，再写进 engine.css、engine.js 的 `LAYOUTS`、build_deck.py 的 `LAYOUTS`、本表和内容呈现分析的决策表。

## 图片与底图（2026-10-06）

单页引擎有两种图：**整页底图**（编辑台「页面 → 底图 → 上传图片」，整套共用一张，压成 WebP 存进课件）和 **卡片配图**（0.3.9，见下）。公共版不包含机构标识素材。

**卡片配图（0.3.9）**：任一卡片加 `pic`，图排在说明下面。内容.json 写 `"pic": {"src": "资料/图片/x.png", "h": 580, "fit": "contain"}`（src 相对内容.json；构建时用 cwebp 压成 WebP，最长边 1600，内嵌）；`h` 是图框高度（120–900），生成卡片时就写定，讲解中尺寸不变；`fit` 截图／表格用 `contain`（完整显示），照片用 `cover`（铺满裁切）。编辑模式卡片右下有「配图／更换配图、图高－＋、改为铺满裁切、去掉配图」，可撤销，保存、导出、JSON 备份都带着。图片须由使用者提供并确认授权。

规范：

- **先问图有没有用**：去掉这张图，观众少知道什么？答不上来就是装饰，不放（花叔的真图测试）。学校实景照片在“讲这所学校”时有用；泛泛的“大学生”素材图没用。
- 使用第三方图片前确认来源和分发授权；本集合不附带照片、截图、标识或字体文件。
- **底图要安静**：透明度 25%–40%，必要时去色或模糊；主体（校门、建筑）避开标题区和右下主播位；标题区、卡片区背后不要有高对比纹理。配「照片衬底」主题包时卡片自带毛玻璃，可以适当提高透明度。
- **铺放**：照片用「铺满（裁切）」，构图重点放画面中部；截图、图表、logo 用「完整显示」，不许裁掉文字和数据（歸藏、html-ppt 都把截图默认 contain）。
- **比例**：画布 4:3（1600×1200）。照片最好原图就是横幅，短边 ≥1200px；引擎会压到最长边 2000px。
- **手机上看**：底图细节在手机上只剩一个色块，别指望观众看清图里的字；图里的关键信息要做成卡片文字。
- **卡片内配图**（0.3.9 已实现，按图框高度定尺寸）：照片 cover、截图 contain；同一页同组图片统一高度；图片不自带标题、页码，标题写在卡片标题里。别人的截图常带公众号水印，交付时告诉用户。
