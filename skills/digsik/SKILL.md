# 学习卡片流

把一次具体失误变成下次用得上的知识。适用于收工捡候选、整理学习记录、按需写学习卡片。不会自动建定时任务。

## 本地输入与能力边界

由用户指定学习目录，使用 `候选.md`、`卡片.json`。结构见 [examples/cards.example.json](examples/cards.example.json)，校验脚本仅使用 Python 3 标准库：

```bash
python3 <本技能>/scripts/validate.py <学习目录>/卡片.json
```

首次创建可复制示例；修改现有 JSON 前在同目录留不覆盖的时间戳备份。仅在用户指定的本地目录读写，不扫描个人资料库。
本包没有网页生成器、iCloud 同步脚本、Artifact 发布器或任何远程账号配置。用户如需同步，应另行提供适配工具、目标位置和相应授权；先核验工具存在。无工具时只完成本地阶段，明确报告“手机/电脑版未同步”，不能把校验通过当作同步成功。

## 收工捡候选

满足至少一条才捡：① 机制会反复出现；② 能解释此前另一件事；③ 不理解会重复踩坑。写不出具体的“下次在哪碰到”就不捡。收工只追加候选，不自动写卡。

追加到 `候选.md` 的“待处理”：

```text
- [ ] 日期 · 记录者 · 项目代号
  坑：真实现象，不补数字
  符合：①/②/③，说明理由
  下次在哪碰到：具体场景
  证据：用户授权范围内的文件或输出
```

## 用户要求整理时

1. 读候选、现有卡片及候选中有权读取的证据。无候选就结束，不声称页面已刷新。
2. 不满足标准的标为丢弃并说明原因；证据不足的保留待处理；只需知道名词的转待展开。
3. 同机制并入已有坑或用 `links` 连接；新机制在 `holes` 末尾增加一项。
4. 根卡写 `gap`（已知 A 与 B 的联系）、`coord`（机制坐标）、`next`（下次应用场景）；深一层卡片每张只讲一件事。面向用户实际背景写，首次出现的陌生术语加入 `terms`。
5. 运行本地校验，通过后将候选改为 `[x] 入卡 → 卡片ID`，移到“已处理”。报告处理数、本地文件和未完成的外部阶段。

事实只来自证据，不补造数字、历史或已验证状态。不发消息、不安装依赖、不创建定时、不推送到未获授权的服务。
