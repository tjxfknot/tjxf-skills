# 企微群书签

本技能在 macOS 企业微信里打开用户指定的置顶会话，向上翻页截图，以系统 Vision 文字识别（OCR）读取消息。只在用户当场要求时运行，不建定时任务。截图和原文属于私人数据，保存在用户指定的本地目录，不发布到代码仓库。

## 必须保留的边界

- 只能用本包受控脚本操作企业微信。禁止用电脑操控工具在群里点击、打字或粘贴；翻页源码仅允许点击固定“消息”导航、会话列表第一行，以及移动和滚动。禁止点击聊天文字、输入框、发送按钮或加入任何键盘事件。
- 用户须把指定群置顶并排第一。首次截图群名不符立即停止，不绕过检查。列表首行被选中会清除未读状态，运行前告知用户。
- 不向群或任何人发消息。误发时立刻告知用户，由用户处理，不代为撤回。
- 写飞书属于外部写入：必须先展示本批书签并核实用户明确指定的文档与插入锚点，获得本次写入授权。仅要求“整理群消息”不等于授权写飞书。缺少目标、授权或兼容工具就交付本地书签。

## 准备

只提供自建 Swift/Python/zsh 源码，不含应用二进制、群资料、文档 ID 或登录状态。
依赖：macOS、已登录企业微信、系统截图工具、Swift 编译器和 Python 3。用户须另行安装/准备依赖；技能不会自动安装。编译和签名会生成本地应用，需用户授权准备后运行 `zsh <本技能>/scripts/编译.sh`。辅助功能与屏幕录制权限由用户自行决定和开启，不能绕过。
本地运行目录默认采用系统当前用户的 Application Support，可统一设置 `WEWORK_BOOKMARK_SUPPORT`；所有脚本须继承同一环境。不要并发抓取两个群。
飞书适配器需要用户自备兼容的 `lark-cli docs +update/+fetch --as user` JSON 接口；本分发版不捆绑该工具，也未验证其他安装的接口兼容性。

## 使用

1. 在用户指定的独立群工作目录中，将 `examples/配置.example.json` 复制为 `配置.json`，填写用户指定的完整群名。不要使用示例占位值。
2. 告知用户接下来企微会置前自动翻页，期间不要操作鼠标；确认窗口位于普通桌面，正确账号已登录。
3. 在该工作目录运行：

```bash
python3 <本技能>/scripts/抓取.py --since "2026-01-01 00:00"
```

已有 `状态.json` 时可省略 `--since`。抓取失败就停，不提交；读取最后输出的本地原文路径。
4. 按原文写同名 `记录/<本次>_书签.txt`，每行 `MM/DD HH:MM · 发言者：事情`，一条一事，优先通知、规则、问题与解决办法、待办和截止时间。问答合并，未答标“暂无回复”。数字、日期和发言人必须有原文证据，不补、不推算；不写手机号、订单号或身份证号。用户自己的消息和寒暄略过。
5. OCR 乱码、⚠ 拼接缺口、群名或时间存疑时对照对应本地截图；仍看不清就不写该条。先把本地书签交给用户检查。
6. 只有飞书目标与写入均明确授权后：

```bash
python3 <本技能>/scripts/写入飞书.py 记录/<本次>_书签.txt --doc <用户指定文档> --block-id <用户指定插入块> --authorize-write
```

脚本会读回核对，成功后才推进 `状态.json`。失败后先检查目标文档是否已插入，禁止盲目重试导致重复。该适配器不建新文档、不发送聊天消息。
7. 汇报书签数、覆盖区间、截图页数、缺口及本地文件；仅实际读回成功才报告飞书已更新。

## 局限和排错

先核对入口、登录/权限、前台状态、置顶选中对象、截图送达和格式。界面固定坐标可能随企业微信版本变化，群名核验不能证明所有布局均适配；布局不符停下维护，不能取消核验。
读不了图片、表情、文件卡片的正文；消息时间是界面分组时间，并非每条精确时间。达到页数上限说明更早内容未覆盖。系统只截桌面时请用户检查录屏权限；Vision 编译产物保持英文名 `wework-ocr`。
