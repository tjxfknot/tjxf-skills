# 装配指南

## 一、装进一份已经存在的 HTML

这是最常见的用法。**先备份，再改**（用户手改过的文件尤其）。

### 情况 A：那份 HTML 是静态的（没有 DATA）

最省事。三步：

1. 给想让人改的元素加 `data-e="唯一名字"`。批量加可以用脚本按标签/class 扫。
2. 页面底部内联 `editdesk.js` 全文。
3. 加一行 `EditDesk.init({ mode:'dom', key:'这份文件的名字' });`

导出走 snapshot（默认自动选），把当前整棵 DOM 克隆下来，编辑台自己的 UI 会剥干净。

缓存里存的是每个 `[data-e]` 的 `innerHTML` **加上它自己的 `style` 属性**
（格式条改的字号颜色落在后者）。**页面顺序不在其中**——
要支持拖动排序的话，宿主自己拿 `MutationObserver` 盯一下 `childList` 另存一份。

### 情况 B：那份 HTML 是数据驱动的

看它有没有自带的旧编辑功能：

- **没有** → 按 SKILL.md 的 data 模式装，注意 `boot` 必须在首次渲染之前。
- **有旧的**（比如从同一个模板衍生出来的老版本）→ 把旧实现**换掉**，别叠加。
  两套 `focusout` 监听会各写一次数据、各存一次，行为会飘。
  **换掉旧实现 = 换了存储键**：旧版存在老 key 里、用户还没导出的东西就读不出来了。
  装之前先让用户用旧文件导出一次，装完在页面里留个检测——发现老 key 还在就弹一句提示。

将旧宿主接入编辑台时，可以参考下面的对应关系（公开副本不附原业务项目）：

| 旧的 | 换成 |
|---|---|
| `localStorage.getItem(...)` + 版本不符 `removeItem` 那一段 | `DATA = EditDesk.boot(DATA, {key, ver, onStaleCache:'keep'})` |
| `function persist(){ localStorage.setItem(...) }` | `function persist(){ EditDesk.save(); }` |
| `function exportHTML(){ …拼文件… }` | `function exportHTML(){ EditDesk.exportHTML(); }` |
| `document.addEventListener('focusout', …)` 整段 | 删掉，改用 `EditDesk.init({ onChange })` |
| 宿主的 `setEditing(v)` 内部 | 末尾加 `EditDesk.syncEditing(v)` |

## 二、宿主自带工具条 / 自带编辑模式

宿主已经有自己的按钮和编辑开关时（它往往还要管面板显隐、聚焦复原），别让核心层再画一套：

```js
EditDesk.init({
  mode:'data', data:DATA, key:'mind985',
  ui:false,                                  // 不注入自带工具条
  onChange: ()=>{ rebuild(); relayout(true); },
  toggleEditing: v => setEditing(v),         // Cmd+E 走宿主自己的开关
  onDirty: v => { 宿主按钮.textContent = v ? '导出 HTML ●' : '导出 HTML'; }
});
```

再在宿主的 `setEditing` 末尾加 `EditDesk.syncEditing(v)`，把状态同步回来。

核心层判断"这个元素能不能改"只看它**当下是不是 contenteditable**，不看自己那个内部标志——
所以谁开的编辑模式都不影响它工作。

## 三、导出两种模式怎么选

| | snapshot（默认） | template |
|---|---|---|
| 怎么导 | 克隆当前整棵 DOM | 用页面启动时存的原始骨架重建 |
| 宿主要配合吗 | 不用 | 要，见下 |
| 适合 | 静态页；运行时不怎么生成 DOM 的页面 | 运行时生成大量节点的（卡片墙、思维导图） |
| 代价 | 会把运行时产物一起写进文件，文件变大、可能首屏闪一下 | 无 |

用 template 的话，宿主要在**第一个 script 的最顶上**存两样：

```js
const SELF_SRC = document.currentScript.textContent;   // 必须最先执行
window.__ED_SELF__ = SELF_SRC;
const BODY_TPL = (()=>{ const c = document.body.cloneNode(true);
  c.querySelectorAll('script').forEach(n=>n.remove()); return c.innerHTML; })();
window.__ED_BODY__ = BODY_TPL;
```

然后 `EditDesk.init({ exportMode:'template', … })`。

把 `editdesk.js` 内联在这个 script **里面**（`SELF_SRC` 之前），导出的文件才会自带编辑台，
用户拿导出的那份还能接着改。

## 四、API 全表

### 装配

```js
EditDesk.boot(defaults, { key, ver, onStaleCache })   // 读缓存，返回该用的数据对象。data 模式渲染前调
EditDesk.init({ … })                                  // 接管编辑，页面渲染完后调
EditDesk.restoreDom(key)                              // dom 模式手动恢复（init 默认已自动做）
```

`init` 的选项：

| 选项 | 默认 | 说明 |
|---|---|---|
| `mode` | `'data'` | `data` / `dom` |
| `data` | `window.DATA` | data 模式的数据对象 |
| `key` | 页面标题 | 缓存键，同一份文件前后要一致 |
| `selector` | `'[data-e]'` | 哪些元素可改 |
| `exportMode` | `'auto'` | `auto` / `template` / `snapshot` |
| `exportName` | 页面标题 | 字符串或函数 |
| `onChange` | — | `(path, value)`，改完怎么重绘 |
| `onEnter` / `onExit` | — | 进出编辑模式 |
| `onDirty` | — | `(bool)` 有/无未导出改动 |
| `toggleEditing` | — | 宿主自己的编辑开关 |
| `panels` | — | 编辑模式下一并显隐的选择器数组 |
| `ui` | `true` | 是否注入自带工具条 |
| `autoRestore` | `true` | dom 模式是否自动恢复缓存 |

`boot` 的 `onStaleCache`：`'keep'`（默认，保住用户的稿 + 弹条提示）/ `'drop'`（直接丢，**别用**）。

### 运行时

```js
EditDesk.setEditing(v)   EditDesk.isEditing()   EditDesk.syncEditing(v)   EditDesk.toggle()
EditDesk.exportHTML()    EditDesk.save()        EditDesk.reset()          EditDesk.isDirty()
EditDesk.data()          EditDesk.getP(p[,o])   EditDesk.setP(p,v[,o])
EditDesk.toast(msg)      EditDesk.clean(html)   EditDesk.plain(html)
```

事件：`window.addEventListener('editdesk:mode', e => e.detail.editing)`

### 自带的键

`Cmd/Ctrl+E` 切编辑模式 · `Cmd/Ctrl+S` 导出 · 编辑中 `Esc` 退出当前格 ·
回车插 `<br>` 不插 `<div>` · 粘贴一律转纯文本

## 五、自带的行为，不用自己写

- 存储防抖 250ms；`localStorage` 满了会提示"赶紧导出"
- 有未导出改动时关页面会拦一下
- 导出按钮带 ● 表示有没导出的改动
- 编辑态的虚线框、hover、focus 样式
- 富文本粘贴净化（只留 `b` / `em` / `br`）
- 打印时自动隐藏所有编辑台 UI
