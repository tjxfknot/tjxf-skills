# 踩过的坑

都是真踩过的。第 1、5 条出过事故，动手前必读。

## 1. 提版本号会删掉用户没导出的编辑 ⚠️ 出过事

**怎么出的**：老代码是"`ver` 对不上就 `localStorage.removeItem()`"。
用户在旧版本里改了很多内容、没导出，我为了让新默认值生效提了 `ver`，
他一打开新版本，**编辑全没了**。

**现在的做法**：`EditDesk.boot` 默认 `onStaleCache:'keep'` ——
版本对不上也**照样把用户的稿读出来用**，只在顶部弹一条提示：

> 这份文件是新版（v2），你本机存着旧版（v1）的修改。**现在显示的是你的修改**，新版的默认内容还没生效。
> ［先导出我的修改］［用新版内容（丢弃我的修改）］［知道了］

丢弃那条要二次确认。**永远别用 `onStaleCache:'drop'`。**

**还有一条铁律**：要给一份用户可能改过的 HTML 提 `ver` 之前，
**先让用户导出一次**。这条已经单独记进记忆（`feedback-export-before-version-bump`）。

## 1.5 同一个缓存键打开不同文件，看到的都是缓存那份 ⚠️ 出过事

**怎么出的**：一个项目迭代了十几版，每版都存进 `版本备份/`。用户打开 `v11` 想看新内容，
看到的却还是他自己那份旧稿——因为所有版本的 `key` 都一样，`boot` 读到缓存就直接用了。
版本号相同时连提示条都不弹，用户会以为"文件没更新"。

**现在的做法**：`boot` 给 defaults 算一个短指纹存进缓存（`_fp`）。
下次打开只要**指纹对不上**（哪怕 `ver` 没变），就当作 stale 弹提示条，文案会说
"多半是换了一份文件、或打开了历史备份"。指纹是内部字段，导出时会剔掉。

提示条还多了一个**「只看一眼文件内容（不动我的稿）」**：
写个 `sessionStorage` 标记后刷新，这一次 `boot` 直接返回文件自带的 defaults，
并且**全程不写缓存**（`persist` 在 `ED._peek` 时直接 return），刷新一下就回到用户自己的稿。
拿它看历史备份最方便。

**旧版本导出的文件没有这个能力**（它们内联的是老 `editdesk.js`），
要看那些文件的原始内容，只能用无痕窗口打开。

## 2. 改完不点导出就没落盘

编辑存在浏览器的 `localStorage` 里，**不点导出，磁盘上的文件一个字没变**。
换台电脑、换个浏览器打开就啥也没有。

运行时已经做了三层提醒：导出按钮带 ●、切编辑模式时 toast 说"改完按导出才算落盘"、
有未导出改动时关页面会拦一下。

**但装完还是要跟用户口头讲一遍。** 这是最容易产生误解的地方。

## 3. TDZ：函数抽出去之后首次调用白屏

`buildTree()` 里引用的变量（如 `MODE`）、函数依赖的常量（如 `paintLogos` 依赖 `INK`），
如果声明写在建树代码**之后**，首次调用直接报错白屏。

抽函数、挪代码的时候盯住声明位置。**改完必须刷新页面看一眼**，
这类错只在首次加载时炸，热更新看不出来。

## 4. 整树重建会丢状态

重建 DOM 会丢掉：展开/折叠、当前选中、**contenteditable**。

所以 `onChange` 里重绘之后要复原：

```js
function render(){
  …重绘…
  if(EditDesk.isEditing()) EditDesk.setEditing(true);   // 把可编辑状态贴回去
}
```

不复原的话，用户改完一个字，剩下的字就都点不动了。

## 5. 运行时被内联进宿主后，自己把自己切断 ⚠️ 这次真出了

**怎么出的**：`template` 导出要做的事是——把 `SELF_SRC`（整个 script 的源码）里
`/*DATA_START*/ … /*DATA_END*/` 之间的内容换成新的 DATA。

而 `editdesk.js` 内联进同一个 script 后，**它自己的源码里也写着这两个标记的字符串字面量**，
而且排在真正的 DATA 块**前面**。非贪婪正则匹配到的是编辑台自己那两行，
一替换就把编辑台的代码从中间切开，留下个没闭合的引号 → `SyntaxError` → 导出的文件白屏。

**现在的做法**：`editdesk.js` 里标记一律拼出来，绝不写成字面量：

```js
var MK_S = '/*DATA' + '_START*/', MK_E = '/*DATA' + '_END*/';
```

**这条的通用教训**：任何"把自己的源码拿来做字符串替换"的代码，
源码里都不能出现它要找的那个标记。宿主页面自己的代码里也别出现。

**也正因为这个坑，第 2 条那种"看着 blob 内容对就算过"的验证不够** ——
blob 里 DATA 块是对的，文件照样打不开。必须真的把导出的文件跑一遍。

## 5.5 dom 模式只存 innerHTML，元素自己的 style 会丢

**怎么出的**：给一份静态页装了格式条，用户改了一批标签的颜色，
刷新之后颜色全没了——`persistDom` 当时只存 `[data-e]` 元素的 `innerHTML`，
而颜色写在元素**自己的 `style` 属性**上，不在 innerHTML 里面。
同理还有：页面顺序（拖动排序）、元素上的 class。

**现在的做法**：`persistDom` 连 `style` 属性一起存进缓存的 `sty` 字段，
`restoreDom` 再贴回去。老缓存没有这个字段也读得动。

**还没管的**：**页面顺序**。那是宿主自己的结构，核心层不该知道，
需要的话宿主自己存一份（拿 `MutationObserver` 盯 `childList` 最省事，
不用逐个去 hook 排序面板的每个操作）。

## 6. 面板浏览器后台会节流

标签页在后台时 `rAF` 不跑、CSS 过渡不推进，量出来的尺寸是错的。
测量前先截个图把页面唤醒；依赖 `rAF` 的代码加 `setTimeout` 兜底。

## 7. 类名撞车

面板分区用 `.grp`、"与上一条同组"也用 `.grp`，
分区的 `flex-direction:column` 漏到了行上，行被拉成三行高。

同一个 CSS 作用域里，**语义不同的东西别用同一个类名**。
这种错肉眼看截图容易忽略（"好像有点高？"），
用 `getBoundingClientRect()` 量一下行高立刻就露馅。
